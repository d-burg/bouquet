All eight files above from `dd_synthetic.json.gz` down are generated by `make_synthetic_fixtures.py` (owner decision D3): analytic profile families
(`Hmode_profiles`, polynomials) with parameters rounded to two significant figures, every slice re-solved
self-consistently by TokaMaker from its kinetics up (pressure including fast ions, Redl bootstrap on the converged
state, beam and ohmic currents), written in COCOS 11 with `j_tor` built on the previous slice as FUSE does. What each
file carries, what the code reads, and what the dependent tests assert: [`FIXTURE_SPEC.md`](FIXTURE_SPEC.md).
Regenerate with `python tests/data/make_synthetic_fixtures.py OUT_DIR` on a machine with OpenFUSIONToolkit (the
`--mesh` option takes a finer machine mesh for the solves; the fixtures are mesh-independent). The regression goldens
(`tests/golden/`) are runs of (the IDS golden) or will be runs of (the g-file goldens) `g_synthetic.geqdsk`,
`diiid_profs_synthetic.cdf` and `dd_synthetic.json.gz`: a change to any of the three moves them, so regenerate the
goldens with it (`tests/golden/README.md`).

Sigma envelopes: every kinetic sigma (the IDA files' `*_err`, the dd's
core_profiles `*_error_upper` on all five slices) is the 2-s.f. radial template
of the fixture's phase -- the median relative envelopes of IDA-lite deliveries
on DIII-D H-mode flat-top / ramp / L-mode slices -- times the profile
([`FIXTURE_SPEC.md`](FIXTURE_SPEC.md) section 7). `python
tests/data/apply_sigma_templates.py [DIR]` rewrites them in place without a solve
(the profiles are checked unchanged bit for bit); the generator calls the same
functions.

Pressure consistency (`test_fixture_pressure_consistency.py`, FIXTURE_SPEC.md
section 8): each g-file's on-axis pressure equals the pressure its profile
file gives on the g-file route within 2 % -- e (n_e T_e + n_i T_i) with n_i
from Z_eff for an IDA-layout file, plus `pb` for the p-file:

| pair | g-file axis | profile file axis | difference |
|------|-------------|-------------------|------------|
| `g_synthetic.geqdsk` + `diiid_profs_synthetic.cdf` | 46.08 kPa | 46.13 kPa (thermal) | -0.09 % |
| `g_synthetic_pfast.geqdsk` + `p_synthetic.peqdsk` | 90.40 kPa | 90.03 kPa (thermal 32.03 + pb 58.00) | +0.42 % (the carbon pressure, in the g-file, not in the route's thermal) |
| `g_synthetic_lmode.geqdsk` + `ida_synthetic_lmode.cdf` | 46.50 kPa | 45.96 kPa (thermal) | +1.16 % (the same carbon term) |

Before 2026-10-15 `g_synthetic.geqdsk` was the total-pressure file (90.4 kPa
against the IDA file's 46.1 kPa), so every reconstruction on the pair recovered
about half its beta_N (0.80 against 1.68). Note that the IDA route's n_i counts
the beam deuterons (Z_eff counts them, and the file has no fast channel): its
"thermal" pressure, 46.1 kPa on axis, includes them at T_i, while the p-file
separates them (thermal pressure 32.0 kPa with the thermal n_i, plus `pb`
58.0 kPa).
